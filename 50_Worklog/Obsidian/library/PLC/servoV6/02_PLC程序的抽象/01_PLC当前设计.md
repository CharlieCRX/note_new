## 设置参数

- 手动速度
- 定位速度
- 使能轴控
- 相对原点清除
- 绝对位置清零
- 绝对定位触发
- 相对定位触发
- 点动正转
- 点动反转
- 报警解除触发
- 使能电机
- 相对定位终止触发
- 绝对定位终止触发
- 相对原点设置	
- 点动心跳
- 告警码置零	
- 相对原点记录	
- 绝对定位距离	
- 相对定位距离	
- 软件负限位	
- 软件正限位	
- 超差阈值		
- 软限位控制

这些定义了一个单轴的所有能够控制的功能。

- 限位状态
- 告警码

这几个就是反馈读取的部分了。

# 综合逻辑

基于上面的思路，我想的初始化逻辑是这样的：

## 配置逻辑

在 PLC 进行运动控制轴的关联后，此时对应的 PLC 轴号（例如L0、C0等）就跟对应现实场景下的电机连接成功了，例如A组：

| 功能轴 | PLC 轴号 |  实际电机号  |      |
| :----: | :------: | :----------: | ---- |
|   X    |   SYN0   | 虚拟轴无实体 |      |
|   X1   |    L0    |      0       |      |
|   X2   |    L1    |      1       |      |
|   Y    |    L2    |      2       |      |
|   Z    |    L3    |      3       |      |
|   R    |    C0    |      4       |      |



这样对应好后，就将其存储到 16 个控制寄存器`职责`（32位的寄存器）中进行记录。

## 上位机启动

启动的时候，首先需要读取 16 个控制寄存器`职责`（32位的寄存器），对每个轴的信息进行处理：

- bit 1: 分组；0-1 对应 A 和 B 组
- bit 2-4(3bits): 轴功能；0-7对应的是X、X1、X2、Y、Z 和 R （例如 X1 编码 1 就是 `0b001`，R 编码 5 就是 `0b101`）
- bit 5: UI 是否展示；0-1对应是否上位机要展示；

这样根据读取出来的结果，进行 16 个单轴的抽象以及 UI 的映射。

然后轮询读取单轴参数和状态反馈，作为实例化的初始信息。

### 联动轴额外的处理

联动轴在上面的基础逻辑上，要额外做联动逻辑。联动轴 X 需要记录额外的配置为：

- 主动轴 X1
- 从动轴 X2
- 是否联动

这部分内容应该放在`职责`寄存器的：

- bit 6 - 9：主动轴号；对应了0-15的单轴编号
- bit 10 - 13：从动轴号；
- bit 14：是否联动；

当且仅当`职责`寄存器证明此轴为联动轴 X （bit 2 - 4 = 0）的时候，这几个位才能正常读取判断；

这样上位机启动的时候，就把 PLC 定义的 16 个轴，根据`职责`寄存器分别实例化了，然后对应好了 UI 控制。
