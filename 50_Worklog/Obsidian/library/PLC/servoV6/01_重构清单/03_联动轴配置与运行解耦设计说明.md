# PLC 轴映射与联动控制设计说明

## 1. 要解决的问题

设备初始化时，需要同时确定两类关系：

1. **单轴映射**

   ```text
   现场电机1 → PLC轴L0 → A组X1
   ```

2. **龙门联动**

   ```text
   A组X逻辑轴 → SYN0
   A组X1 → L0，基准侧
   A组X2 → L1，跟随侧
   ```

当前程序只保存运行期联动成员，解除联动后会丢失关系；单轴的业务功能映射也没有统一保存。

因此需要一份完整的设备配置，让PLC和上位机都能回答：

```text
某个现场电机绑定了哪个PLC轴？
某个PLC轴在设备中承担什么功能？
A组X1、Y、Z、R分别对应哪个PLC轴？
某个SYN逻辑轴包含哪些成员？
```

---

## 2. 设计结论

推荐按“设备组”保存完整配置：

```text
设备配置
├─ A组
│  ├─ 单轴映射：X、X1、X2、Y、Z、R、俯仰
│  └─ 龙门规则：X由X1和X2组成
└─ B组
   ├─ 单轴映射：X、X1、X2、Y、Z、R、俯仰
   └─ 龙门规则：X由X1和X2组成
```

其中：

- **轴映射**是唯一的数据源；
- **龙门配置引用功能轴**，不重复保存L0、L1、SYN0；
- PLC在配置生效时，将功能轴解析成实际PLC轴号；
- 建立和解除联动只改变运行状态，不修改设备配置。

---

## 3. 三层关系

### 3.1 现场设备层

描述现场可识别的电机编号：

```text
电机1、电机2……电机10
```

电机编号用于安装、调试、报警和维护。

### 3.2 PLC运动轴层

描述AutoShop中的运动控制轴：

| PLC轴      |   索引 | 类型                   |
| ---------- | -----: | ---------------------- |
| L0～L9     |   0～9 | 线性物理轴，单位mm     |
| L10～L12   | 10～12 | 旋转物理轴，单位°      |
| SYN0～SYN2 | 13～15 | 联动逻辑轴，无独立电机 |

### 3.3 业务功能层

描述上位机和操作人员理解的功能：

```text
X、X1、X2、Y、Z、R、Pitch
```

上位机控制的是业务功能轴，不应在业务代码中到处硬编码L0、L1等PLC轴号。

---

## 4. 统一的数据结构

以下结构用于说明逻辑，实际字段名称可根据AutoShop编程规范调整。

### 4.1 功能轴编号

```text
0 = X       龙门逻辑轴
1 = X1      龙门基准侧
2 = X2      龙门跟随侧
3 = Y
4 = Z
5 = R
6 = Pitch   预留俯仰轴
```

建议PLC和上位机共同使用固定编号，不使用可变字符串参与控制。

### 4.2 单个轴映射

```pascal
TYPE ST_AxisBinding :
STRUCT
    Valid       : BOOL;  // 本映射是否启用
    FunctionNo  : INT;   // X/X1/X2/Y/Z/R/Pitch
    PlcAxisNo   : INT;   // 0～15，对应L0～SYN2
    MotorNo     : INT;   // 现场电机编号；SYN逻辑轴填0
END_STRUCT
END_TYPE
```

字段含义：

| 字段         | 说明                                  |
| ------------ | ------------------------------------- |
| `Valid`      | 当前功能轴是否存在                    |
| `FunctionNo` | 该轴在设备中的用途                    |
| `PlcAxisNo`  | 对应的PLC运动轴索引                   |
| `MotorNo`    | 对应现场电机编号；逻辑轴没有电机，填0 |

不需要在配置中保存：

- `M128`、`D1000`等寄存器地址；
- 当前是否使能轴控；
- 当前是否`InGear`；
- 当前错误码。

这些都不是长期拓扑。

### 4.3 龙门规则

```pascal
TYPE ST_GantryRule :
STRUCT
    Valid             : BOOL;  // 是否配置龙门
    SynFunctionNo     : INT;   // 固定引用X
    ReferenceFunction : INT;   // 固定引用X1
    FollowFunction    : INT;   // 固定引用X2
    ReferenceRatio    : INT;   // 通常+1
    FollowRatio       : INT;   // 根据机械方向取+1或-1
    RatioDenominator  : INT;   // 通常为1
END_STRUCT
END_TYPE
```

龙门规则引用的是：

```text
X、X1、X2
```

而不是再次保存：

```text
SYN0、L0、L1
```

这样可以避免两套配置不一致。

### 4.4 设备组配置

```pascal
TYPE ST_MachineGroupConfig :
STRUCT
    Valid         : BOOL;
    GroupNo       : INT;  // 0=A组，1=B组
    AxisBindings  : ARRAY[0..6] OF ST_AxisBinding;
    Gantry        : ST_GantryRule;
END_STRUCT
END_TYPE
```

完整设备配置：

```pascal
TYPE ST_MachineConfig :
STRUCT
    FormatVersion : INT;
    ConfigVersion : UDINT;
    Groups        : ARRAY[0..1] OF ST_MachineGroupConfig;
    ConfigCrc     : UDINT;
END_STRUCT
END_TYPE
```

`ST_MachineConfig`整体存放在PLC掉电保持区。

## 5. A组和B组配置示例

### 5.1 A组

| 功能  | PLC轴     | 电机 | 说明       |
| ----- | --------- | ---: | ---------- |
| X     | SYN0 / 13 |    0 | 龙门逻辑轴 |
| X1    | L0 / 0    |    1 | 龙门基准侧 |
| X2    | L1 / 1    |    2 | 龙门跟随侧 |
| Y     | L2 / 2    |    3 | 单轴       |
| Z     | L3 / 3    |    4 | 单轴       |
| R     | L10 / 10  |    5 | 旋转单轴   |
| Pitch | 未配置    |    0 | 预留       |

龙门规则：

```text
逻辑轴：X
基准侧：X1，比例+1/1
跟随侧：X2，比例-1/1
```

PLC解析后得到：

```text
MC_GearIn 1：Master=SYN0，Slave=L0，Ratio=+1/1
MC_GearIn 2：Master=SYN0，Slave=L1，Ratio=-1/1
```

### 5.2 B组

| 功能  | PLC轴     | 电机 | 说明       |
| ----- | --------- | ---: | ---------- |
| X     | SYN1 / 14 |    0 | 龙门逻辑轴 |
| X1    | L4 / 4    |    6 | 龙门基准侧 |
| X2    | L5 / 5    |    7 | 龙门跟随侧 |
| Y     | L6 / 6    |    8 | 单轴       |
| Z     | L7 / 7    |    9 | 单轴       |
| R     | L11 / 11  |   10 | 旋转单轴   |
| Pitch | 未配置    |    0 | 预留       |

## 6. 为什么不保存寄存器地址

设备配置只保存：

```text
功能轴 → PLC轴号
```

例如：

```text
A.X1 → PlcAxisNo=0
```

上位机再根据通信协议表计算或查询地址：

```text
PlcAxisNo=0
→ 使能电机[0]
→ 手动速度[0]
→ 绝对定位距离[0]
→ 轴状态[0]
```

不建议在PLC配置中保存具体地址，原因是：

- 地址属于通信协议，不属于机械拓扑；
- PLC变量布局变化后，旧地址会失效；
- 同一轴包含速度、位置、状态、报警等多个地址，不可能只保存一个；
- 直接保存地址会让上位机绕过协议版本管理。

正确方式是：

```text
设备配置给出PlcAxisNo
+ 通信协议版本给出各数组基址和数据类型
= 上位机得到实际访问位置
```

## 7. 上位机启动流程

上位机连接PLC后：

```text
1. 读取协议版本；
2. 读取设备配置版本和CRC；
3. 读取A组、B组全部轴映射；
4. 读取龙门规则；
5. 读取当前运行状态；
6. 建立本地功能索引；
7. 配置合法后进入运行界面。
```

上位机建立如下索引：

```text
A.X  → SYN0
A.X1 → L0
A.X2 → L1
A.Y  → L2
A.Z  → L3
A.R  → L10
```

业务代码调用：

```text
MoveVelocity(A, Y, 10 mm/s)
```

通信层执行：

```text
A.Y
→ 查询配置得到PlcAxisNo=2
→ 访问手动速度[2]和对应控制位
```

业务层不需要知道Y当前是L2。

## 8. PLC配置解析

PLC不应在每个扫描周期反复解析全部配置。

建议在以下时机解析：

- PLC上电；
- 新配置提交成功；
- 配置恢复完成。

解析结果保存在运行缓存中：

```pascal
TYPE ST_ResolvedGantry :
STRUCT
    Valid             : BOOL;
    SynAxisNo         : INT;
    ReferenceAxisNo   : INT;
    FollowAxisNo      : INT;
    ReferenceRatio    : INT;
    FollowRatio       : INT;
    RatioDenominator  : INT;
END_STRUCT
END_TYPE
```

例如A组解析结果：

```text
SynAxisNo       = 13
ReferenceAxisNo = 0
FollowAxisNo    = 1
ReferenceRatio  = +1
FollowRatio     = -1
```

该缓存只用于PLC运行，不是长期配置的第二数据源。

## 9. 单轴控制逻辑

对于Y、Z、R、Pitch等独立轴：

```text
上位机发送“控制A组Y轴”
→ 根据配置解析为L2
→ 访问索引2对应的速度、位置和控制变量
```

对于X1、X2：

- 未联动时，可以在维护模式下独立点动；
- 已联动或正在建立联动时，禁止接收独立运动命令；
- 禁止独立轴控不等于关闭电机使能；
- 禁止独立轴控不等于删除X1/X2映射。

对于X：

- X映射到SYN逻辑轴；
- 只有龙门状态为“已联动”时才能接受运动命令；
- X没有现场电机编号。

## 10. 联动运行数据

长期配置和运行状态必须分开。

### 10.1 运行命令

```pascal
TYPE ST_GantryCommand :
STRUCT
    EnableRequest : BOOL;   // TRUE建立，FALSE解除
    ResetRequest  : BOOL;
    CommandId     : UDINT;
END_STRUCT
END_TYPE
```

### 10.2 运行状态

```pascal
TYPE ST_GantryStatus :
STRUCT
    State              : INT;
    SynAxisReady       : BOOL;
    ReferenceAxisReady : BOOL;
    FollowAxisReady    : BOOL;
    ReferenceInGear    : BOOL;
    FollowInGear       : BOOL;
    Error              : BOOL;
    ErrorStage         : INT;
    ErrorAxisNo        : INT;
    ErrorCode          : DWORD;
    CompletedCommandId : UDINT;
END_STRUCT
END_TYPE
```

状态值：

|   值 | 状态       |
| ---: | ---------- |
|    0 | 未配置     |
|    1 | 已解除     |
|    2 | 等待轴就绪 |
|    3 | 建立中     |
|    4 | 已联动     |
|    5 | 停止中     |
|    6 | 解除中     |
|    7 | 故障       |

## 11. 联动建立流程

上位机只发送：

```text
建立A组龙门
```

PLC执行：

```text
1. 读取A组已解析的龙门配置；
2. 禁止X1、X2独立运动；
3. 检查SYN0、L0、L1的MC_Power.Status；
4. 检查成员无报警、无独立运动；
5. 对L0和L1分别执行MC_GearIn；
6. 两个成员均InGear后，状态置为“已联动”；
7. 允许X/SYN0接受运动命令。
```

如果只有一个成员建立成功：

```text
禁止X运动
→ 对已成功成员执行MC_GearOut
→ 整组进入故障
→ 返回失败轴号和原始错误码
```

禁止在半联动状态下继续运行。

---

## 12. 联动解除流程

上位机发送：

```text
解除A组龙门
```

PLC执行：

```text
1. 禁止新的X运动命令；
2. 停止SYN0并等待速度为0；
3. 对L0、L1执行MC_GearOut；
4. 等待两个成员均解除；
5. 恢复X1、X2的维护模式独立控制权限；
6. 状态置为“已解除”；
7. 保留A组全部轴映射和龙门规则。
```

关闭SYN轴控也只允许触发上述安全解除流程，不能删除设备配置。

## 13. 配置校验

配置提交时，PLC至少检查：

- 每个有效功能轴只能映射一个PLC轴；
- 同一个PLC轴不能映射到两个不同功能；
- 同一个现场电机不能重复绑定；
- 物理轴必须有电机编号；
- SYN逻辑轴的电机编号必须为0；
- X必须映射到SYN0～SYN2；
- X1、X2必须映射到物理线性轴；
- R必须映射到旋转轴L10～L12；
- 龙门规则引用的X、X1、X2都已配置；
- X、X1、X2属于同一个设备组；
- 比例分母大于0；
- 相关龙门处于已解除状态才能修改配置。

需要注意：该映射描述控制系统的逻辑关系，并不能自动修改AutoShop/EtherCAT中的实际驱动绑定。PLC配置必须与实际总线轴绑定一致，否则应报“硬件绑定不一致”。

## 14. 配置保存与提交

PLC保存两份区域：

```text
MachineConfigStaging   // 上位机正在编辑
MachineConfigActive    // 当前正式生效，掉电保持
```

提交流程：

```text
1. 上位机写完整Staging；
2. 上位机发送Apply和CommandId；
3. PLC校验整套配置；
4. 校验通过后整体复制到Active；
5. PLC重新生成运行缓存；
6. 更新ConfigVersion和CRC；
7. 返回提交结果。
```

建立联动、解除联动、关闭轴控均不能修改`MachineConfigActive`。

删除或修改配置必须使用单独的工程师命令。

## 15. 对现有程序的改造

现有：

```text
联动成员信息[]
联动轴信息[]
MC_GearIn / MC_GearOut固定实例
```

可以继续作为运行期工作区使用。

新增：

```text
MachineConfigActive
MachineConfigStaging
ResolvedGantry[0..1]
GantryCommand[0..1]
GantryStatus[0..1]
```

程序关系调整为：

```text
MachineConfigActive
→ 解析单轴映射和龙门关系
→ 生成ResolvedGantry
→ 建立时装载现有联动成员信息
→ 执行现有MC_GearIn/MC_GearOut
```

解除时只清理运行期Execute、Busy和临时成员信息，不清理`MachineConfigActive`。

## 16. 推荐的职责边界

### PLC负责

- 保存正式设备配置；
- 校验电机、PLC轴、功能轴关系；
- 解析龙门成员；
- 建立和解除联动；
- 故障回退；
- 维护真实运行状态。

### 上位机负责

- 初始化配置界面；
- 读取并展示PLC正式配置；
- 将业务功能轴转换为PLC轴索引；
- 根据协议版本访问对应变量；
- 下发单轴命令和联动命令；
- 展示状态、报警和配置错误。

### 上位机不负责

- 单独保存唯一的机器拓扑；
- 根据当前`InGear`反推长期配置；
- 根据`使能轴控=false`判断映射丢失；
- 在业务层硬编码L0、L1、寄存器地址；
- 绕过PLC状态机直接操作联动功能块。

## 17. 最终结构

最终建议结构如下：

```text
MachineConfigActive
├─ ConfigVersion
├─ A组
│  ├─ AxisBindings
│  │  ├─ X  → SYN0，无电机
│  │  ├─ X1 → L0，电机1
│  │  ├─ X2 → L1，电机2
│  │  ├─ Y  → L2，电机3
│  │  ├─ Z  → L3，电机4
│  │  └─ R  → L10，电机5
│  └─ Gantry：X = X1 + X2
└─ B组
   ├─ AxisBindings
   └─ Gantry
```

这套结构只保存一次轴号：

- 单轴控制通过`AxisBindings`找到PLC轴；
- 龙门控制通过功能轴X、X1、X2引用同一份映射；
- 上位机和PLC都不会维护第二套重复的SYN0、L0、L1关系；
- 建立和解除联动不会破坏初始化配置。

核心原则是：

> 先保存“电机—PLC轴—功能轴”的统一映射，再让单轴控制和联动控制共同引用这份映射。
