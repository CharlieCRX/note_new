# PLC 轴告警码拆分设计与实施规划

## 1. 文档信息

- 适用工程：`PLC_re`、`servoV6`
- 文档状态：设计评审稿
- 目标版本：下一版 PLC/上位机协议联调版本
- 核心目标：将运动限制、操作提示、可复位故障和系统故障解耦，消除“任意告警非零即禁止定位”的错误行为

## 2. 背景与当前问题

当前 PLC 使用 `告警码[0..15]` 的 WORD 位域表达多种状态：

| 当前位 | 当前含义 |
|---|---|
| bit0 | 急停 |
| bit1 | 目标联动轴已有同位置轴，加入失败 |
| bit2 | 目标联动轴已有不同位置轴且超差，加入失败 |
| bit3 | 联动成员信息配置错误，加入失败 |
| bit4 | 联动运行超差 |
| bit5 | 功能块、轴或伺服错误 |
| bit6 | 点动心跳超时 |

现有设计存在以下问题。

### 2.1 不同性质的状态混在同一个字中

以下状态的处理方式完全不同，却共用 `告警码`：

- 正负软件限位：只应限制危险方向，并自动恢复；
- 点动心跳超时：只应终止当前点动；
- 联动加入失败：只应拒绝本次配置命令；
- 伺服或轴故障：应停止运动并等待复位；
- PLC内部故障：应禁止运行并通知维护人员。

当上位机采用 `告警码 != 0` 判断轴故障时，上述状态全部被错误提升为 `AxisState::Error`。

### 2.2 限位后的撤离方式没有形成明确安全规则

当前正限位逻辑同时清除：

```st
轴MoveDo[轴号] := FALSE;
轴MoveXDDo[轴号] := FALSE;
轴JogForward[轴号] := FALSE;
```

当前代码表现为：

- 正限位时，负向点动可以退出；
- 正限位时，所有绝对/相对定位均被终止。

本次设计明确采用更严格的现场安全规则：

> - 触碰任何软件限位或工作硬限位后，只允许使用安全方向的点动低速撤离；
>
> - 限位有效期间禁止所有绝对定位和相对定位。
>
> - 退出限位并满足回差条件后，才能重新开放位置移动。

因此，现有“限位时清除两个定位执行位”的动作原则上保留，但需要补充统一的启动前检查、方向性点动许可、自动恢复条件和明确的上位机提示。

### 2.3 bit5 范围过大

当前 bit5 将下列条件合并：

```st
轴指令错误
OR 轴伺服错误码 <> 0
OR 轴错误码 <> 0
OR 轴伺服DIStatus = 1
OR 轴伺服DIStatus = 2
OR NOT 轴Status
```

其中“轴未使能”是正常状态，不应直接产生故障；命令错误、PLCopen 功能块错误、轴错误和驱动器错误也需要不同的恢复方式。

### 2.4 清除接口会覆盖真实状态

当前 `告警码置零` 直接执行：

```st
告警码[i] := 0;
```

该操作没有区分：

- 当前仍然存在的活动故障；
- 已经消失但尚未确认的锁存故障；
- 只用于历史追踪的事件。

## 3. 设计原则

1. 运动限制不是轴故障，不进入 `AxisState::Error`。
2. 限位有效时禁止所有位置移动，只允许安全方向点动撤离。
3. 活动状态由 PLC 根据现场条件实时计算，不允许通过写零永久隐藏。
4. “告警确认”“故障复位”“历史清除”是三个不同动作。
5. 上位机不得使用 `任意状态字非零` 推导轴故障。
6. PLC 输出明确的运动许可，上位机尽量不重复猜测 PLC 条件。
7. 保留轴内核、PLCopen 功能块和伺服驱动器的原始错误码。
8. 软件限位退出可以自动恢复；系统级故障只能由管理员或维护流程处理。

## 4. 目标状态模型

建议将现有 `告警码` 拆为五组数据。

### 4.1 运动限制 `MotionConstraintBits`

实时、非锁存、方向性限制。

| 位 | 名称 | 含义 | 动作 | 清除条件 |
|---|---|---|---|---|
| bit0 | PositiveSoftLimit | 正软件限位 | 禁止全部定位和正向点动；允许负向点动 | 负向点动退出边界并越过回差 |
| bit1 | NegativeSoftLimit | 负软件限位 | 禁止全部定位和负向点动；允许正向点动 | 正向点动退出边界并越过回差 |
| bit2 | PositiveWorkLimit | 正工作硬限位 | 禁止全部定位和正向点动；允许负向点动 | 负向点动至正限位开关释放 |
| bit3 | NegativeWorkLimit | 负工作硬限位 | 禁止全部定位和负向点动；允许正向点动 | 正向点动至负限位开关释放 |
| bit4 | PositiveUltimateLimit | 正极限限位（如有） | 按安全策略停止 | 人工检查和复位 |
| bit5 | NegativeUltimateLimit | 负极限限位（如有） | 按安全策略停止 | 人工检查和复位 |

说明：

- 工作限位只允许通过反方向点动撤离，不允许使用绝对或相对定位撤离。

- 安全极限限位允许点动撤离。

- 此状态仅在运行过程中出现，用来提示当前运动状态停止的原因

  > 例如正向点动遇到了正限位，此时电机停止运行，并且`MotionConstraintBits[0].0` = 1 ，此时上位机就可以知道运行到了正软件限位后停止了。
  >
  > 此时如果反向点动撤离了限位状态，则`MotionConstraintBits[0].0` = 0，此时上位机就可以感知运行状态是正常的；

- 此状态位，在运行正常（或者从异常到正常后），均为0（自动置为0，不需要手动复位）

### 4.2 操作提示 `WarningBits`

非阻断提示，不把轴切换为 Faulted。

| 位 | 名称 | 含义 | 设备动作 |
|---|---|---|---|
| bit0 | `JogHeartbeatTimeout` | 点动心跳超时 | 终止当前点动 |
| bit1 | `PositionMoveRejectedByLimit` | 任一限位有效时请求位置移动 | 拒绝本次命令，提示仅允许点动撤离 |
| bit2 | `JogRejectedByPositiveLimit` | 正限位状态下请求正向点动 | 拒绝本次命令 |
| bit3 | `JogRejectedByNegativeLimit` | 负限位状态下请求负向点动 | 拒绝本次命令 |
| bit4 | `AbsoluteTargetOutOfRange` | 绝对目标超出软限位范围 | 拒绝本次定位 |
| bit5 | `RelativeTargetOutOfRange` | 相对定位终点超出软限位范围 | 拒绝本次定位 |
| bit6 | `CommandNotAllowedInState` | 当前状态不允许该命令 | 拒绝本次命令 |

说明：

- Warning 可以显示、确认和记录，但不得直接作为 `AxisState::Error` 的依据。
- bit5  `RelativeTargetOutOfRange`：最终要将相对定位终点换算为绝对位置，然后判断绝对位置是否超出了软限位；
- 如何解除`WarningBits`：
  - 手动确认解除
  - 自动解除：下一次操作只要没问题，就自动置为 0 

### 4.3 命令结果 `LastCommandResult`

联动加入失败和参数配置失败属于一次命令的结果，不应长期污染轴状态。

建议输出：

```text
LastCommandResult       WORD
LastCommandDetail       WORD
LastCommandSequence     WORD
```

建议结果码：

| 结果码 | 名称 | 含义 |
|---:|---|---|
| 0 | Success | 命令成功 |
| 1 | PositiveLimitRejected | 正限位拒绝 |
| 2 | NegativeLimitRejected | 负限位拒绝 |
| 3 | TargetOutOfRange | 目标超范围 |
| 10 | CouplingSlotOccupied | 联动槽位已有成员 |
| 11 | CouplingPositionMismatch | 联动成员位置超差 |
| 12 | CouplingConfigInvalid | 联动配置非法 |
| 20 | InvalidParameter | 参数非法 |
| 21 | InvalidAxisState | 轴状态不允许执行 |

每次命令完成或被拒绝时递增 `LastCommandSequence`，避免上位机因轮询周期错过短时事件。

### 4.4 可复位轴故障 `AxisFaultBits`

阻止普通点动和定位，但原因消失后允许执行轴复位。

| 位 | 名称 | 来源 | 建议恢复方式 |
|---|---|---|---|
| bit0 | ServoDriveFault | `轴伺服错误码 <> 0` | 排除驱动故障后复位驱动/轴 |
| bit1 | AxisKernelFault | `轴错误码 <> 0` | 排除轴错误后执行 MC_Reset |
| bit2 | MotionFbFault | 运动功能块 Error | 撤销 Execute、修正条件并复位 |
| bit3 | GantryDeviationFault | 联动运行持续超差 | 停止联动、检查位置并人工复位 |
| bit4 | EnableTimeout | 请求使能后超时未成功 | 检查使能链路并复位 |
| bit5 | HomingFault | 回零失败或超时 | 检查原点信号后重新回零 |
| bit6 | MotionTimeout | 定位执行超时 | 检查机械和参数后复位 |

`NOT 轴Status` 不再直接置故障。只有在“存在使能请求且规定时间内未达到使能状态”时，才设置 `EnableTimeout`。

### 4.5 系统级故障 `SystemFaultBits`

需要管理员、维护人员或控制器恢复流程处理。

| 位 | 名称 | 典型场景 |
|---|---|---|
| bit0 | PlcRuntimeFault | PLC运行时或程序异常 |
| bit1 | CriticalConfigFault | 轴映射、职责或硬件组态不一致 |
| bit2 | FieldbusFault | EtherCAT或关键总线无法恢复 |
| bit3 | SafetySystemFault | 安全链路诊断失败 |
| bit4 | PersistentMotionSubsystemFault | 多次复位仍不能恢复的运动子系统错误 |

系统故障阻止相关设备全部运动，并提示管理员。PLC重启只能作为维护流程中的动作，不应是普通功能块错误的默认恢复方式。

## 5. 现有告警位迁移方案

| 现有位 | 现有含义 | 新归属 | 是否阻止单轴定位 |
|---|---|---|---|
| bit0 | 急停 | SafetyState | 是 |
| bit1 | 联动槽位冲突 | LastCommandResult | 否 |
| bit2 | 联动加入位置超差 | LastCommandResult | 否 |
| bit3 | 联动配置错误 | LastCommandResult；严重时 SystemFault | 通常否 |
| bit4 | 联动运行超差 | AxisFaultBits.GantryDeviationFault | 是，限制相关联动轴 |
| bit5 | 功能块/轴/伺服错误 | 拆分到 AxisFaultBits 和详细错误码 | 是 |
| bit6 | 点动心跳超时 | WarningBits.JogHeartbeatTimeout | 否 |

## 6. PLC 实现设计

### 6.1 新增内部变量

建议为每轴新增以下变量，物理寄存器地址在完成 Modbus 地址冲突审计后确定：

```st
运动限制位           : ARRAY[0..15] OF WORD;
警告提示位           : ARRAY[0..15] OF WORD;
轴故障位             : ARRAY[0..15] OF WORD;
系统故障位           : ARRAY[0..15] OF WORD;
最后命令结果         : ARRAY[0..15] OF WORD;
最后命令详细码       : ARRAY[0..15] OF WORD;
最后命令序号         : ARRAY[0..15] OF WORD;
运动功能块错误码     : ARRAY[0..15] OF DWORD;
轴原始错误码         : ARRAY[0..15] OF DWORD;
伺服原始错误码       : ARRAY[0..15] OF DWORD;
正向点动允许         : ARRAY[0..15] OF BOOL;
负向点动允许         : ARRAY[0..15] OF BOOL;
定位运动允许         : ARRAY[0..15] OF BOOL;
需要故障复位         : ARRAY[0..15] OF BOOL;
需要管理员处理       : ARRAY[0..15] OF BOOL;
```

### 6.2 软件限位实时计算

软件限位采用置位阈值和恢复阈值，避免边界抖动：

```st
IF 软限位控制[轴号].0 THEN
    IF NOT 运动限制位[轴号].0 THEN
        IF 轴CurPosition[轴号] >= 软件正限位[轴号] THEN
            运动限制位[轴号].0 := TRUE;
        END_IF;
    ELSE
        IF 轴CurPosition[轴号] < 软件正限位[轴号] - 限位回差[轴号] THEN
            运动限制位[轴号].0 := FALSE;
        END_IF;
    END_IF;
ELSE
    运动限制位[轴号].0 := FALSE;
END_IF;

IF 软限位控制[轴号].1 THEN
    IF NOT 运动限制位[轴号].1 THEN
        IF 轴CurPosition[轴号] <= 软件负限位[轴号] THEN
            运动限制位[轴号].1 := TRUE;
        END_IF;
    ELSE
        IF 轴CurPosition[轴号] > 软件负限位[轴号] + 限位回差[轴号] THEN
            运动限制位[轴号].1 := FALSE;
        END_IF;
    END_IF;
ELSE
    运动限制位[轴号].1 := FALSE;
END_IF;
```

初始 `限位回差` 应按机械单位和编码器分辨率确定，不建议在所有轴上硬编码同一个经验值。

### 6.3 点动方向许可与定位许可计算

```st
正向点动允许[轴号] :=
    NOT 运动限制位[轴号].0
    AND NOT 运动限制位[轴号].2
    AND NOT 运动限制位[轴号].4
    AND 轴故障位[轴号] = 0
    AND 系统故障位[轴号] = 0
    AND NOT 急停有效;

负向点动允许[轴号] :=
    NOT 运动限制位[轴号].1
    AND NOT 运动限制位[轴号].3
    AND NOT 运动限制位[轴号].5
    AND 轴故障位[轴号] = 0
    AND 系统故障位[轴号] = 0
    AND NOT 急停有效;

定位运动允许[轴号] :=
    轴Status[轴号]
    AND 运动限制位[轴号] = 0
    AND 轴故障位[轴号] = 0
    AND 系统故障位[轴号] = 0
    AND NOT 急停有效;
```

许可规则如下：

- 未触发限位时，点动和定位按正常条件执行；
- 正限位有效时，只允许负向点动；
- 负限位有效时，只允许正向点动；
- 任意软件限位或工作硬限位有效时，`定位运动允许=FALSE`；
- 安全极限限位默认禁止全部运动，是否提供专用维护撤离模式另行安全评审。

### 6.4 命令启动前检查

绝对定位：

```st
绝对目标方向正 := 绝对定位距离[轴号] > 轴CurPosition[轴号] + 位置容差[轴号];
绝对目标方向负 := 绝对定位距离[轴号] < 轴CurPosition[轴号] - 位置容差[轴号];

IF 绝对定位沿触发.Q THEN
    IF 运动限制位[轴号] <> 0 THEN
        记录命令拒绝(CMD_ABS_MOVE, RESULT_LIMIT_ACTIVE_JOG_ESCAPE_ONLY);
    ELSIF NOT 定位运动允许[轴号] THEN
        记录命令拒绝(CMD_ABS_MOVE, RESULT_AXIS_FAULTED);
    ELSIF 绝对定位距离[轴号] > 软件正限位[轴号]
       OR 绝对定位距离[轴号] < 软件负限位[轴号] THEN
        记录命令拒绝(CMD_ABS_MOVE, RESULT_TARGET_OUT_OF_RANGE);
    ELSE
        轴MovePosition[轴号] := 绝对定位距离[轴号];
        轴MoveDo[轴号] := TRUE;
    END_IF;
END_IF;
```

相对定位同样必须首先检查 `运动限制位[轴号] = 0`。限位有效时，无论相对距离方向如何，都拒绝相对定位。未触发限位时，再计算最终位置：

```st
相对最终位置 := 轴CurPosition[轴号] + 相对定位距离[轴号];
```

然后检查最终位置是否越界。

### 6.5 运行中限位保护

启动前检查不能替代运行时保护。任何位置移动在运行过程中触发任一限位，都必须停止；点动则只停止危险方向，保留反方向点动撤离能力：

```st
IF 运动限制位[轴号] <> 0 THEN
    // 限位状态下禁止所有位置移动，包括反方向撤离定位
    轴MoveDo[轴号] := FALSE;
    轴MoveXDDo[轴号] := FALSE;
END_IF;

IF NOT 正向点动允许[轴号] THEN
    轴JogForward[轴号] := FALSE;
END_IF;

IF NOT 负向点动允许[轴号] THEN
    轴JogBackward[轴号] := FALSE;
END_IF;
```

只有点动将轴带离限位区域、限位输入释放并满足软件限位回差后，`运动限制位` 才自动清零，随后恢复位置移动许可。

### 6.6 点动心跳超时

保留 3 秒超时停止保护，但不再设置阻断故障：

```st
IF 点动终止[轴号] THEN
    轴JogForward[轴号] := FALSE;
    轴JogBackward[轴号] := FALSE;
    点动正转[轴号] := FALSE;
    点动反转[轴号] := FALSE;
    点动终止[轴号] := FALSE;

    警告提示位[轴号].0 := TRUE;
    记录事件(EVT_JOG_HEARTBEAT_TIMEOUT);
END_IF;
```

该 Warning 可以保持到上位机确认或下一次有效点动会话建立，但不能参与定位许可。

### 6.7 拆分 bit5

建议替换原有大条件：

```st
轴故障位[轴号].0 := 轴伺服错误码[轴号] <> 0;
轴故障位[轴号].1 := 轴错误码[轴号] <> 0;
轴故障位[轴号].2 := 运动功能块错误有效[轴号];
轴故障位[轴号].3 := 联动超差故障有效[轴号];

伺服原始错误码[轴号] := 轴伺服错误码[轴号];
轴原始错误码[轴号] := 轴错误码[轴号];
运动功能块错误码[轴号] := 当前运动功能块ErrorID[轴号];
```

`轴指令错误` 必须继续拆解：

- 参数或状态不允许：写入 `LastCommandResult`；
- 功能块执行后 `Error=TRUE`：写入 `AxisFaultBits.MotionFbFault`；
- `CommandAborted`：根据终止原因记录事件，不必统一视为设备故障。

### 6.8 复位与确认

新增三个独立命令：

```text
警告确认请求
轴故障复位请求
历史事件清除请求
```

复位规则：

```st
IF 轴故障复位请求[轴号] THEN
    IF 故障物理条件均已消失 THEN
        轴Reset[轴号] := TRUE;
    END_IF;
    轴故障复位请求[轴号] := FALSE;
END_IF;
```

活动故障位必须依据真实条件重新计算，不能通过直接写 `轴故障位 := 0` 清除。

## 7. servoV6 实现设计

### 7.1 协议模型修改

将：

```cpp
int16_t alarmCode;
```

替换为：

```cpp
struct AxisDiagnostics {
    std::uint16_t motionConstraints = 0;
    std::uint16_t warnings = 0;
    std::uint16_t axisFaults = 0;
    std::uint16_t systemFaults = 0;
    std::uint16_t lastCommandResult = 0;
    std::uint16_t lastCommandDetail = 0;
    std::uint16_t lastCommandSequence = 0;
    std::uint32_t motionFbErrorId = 0;
    std::uint32_t axisErrorId = 0;
    std::uint32_t servoErrorId = 0;
};
```

### 7.2 状态推导修改

删除：

```cpp
if (d100State == 3 || alarmCode != 0) {
    return AxisState::Error;
}
```

改为只根据真正故障推导：

```cpp
const bool faulted = diagnostics.axisFaults != 0
                  || diagnostics.systemFaults != 0;

if (faulted) {
    return AxisState::Error;
}
```

限位和 Warning 不改变轴运动状态。

### 7.3 命令策略修改

点动策略检查方向许可；绝对定位和相对定位只要检测到任何限位有效，就拒绝启动：

```cpp
if (command.isPositionMove() && axis.motionConstraints() != 0) {
    return CommandRejected::LimitActiveJogEscapeOnly;
}

if (command.isJog()
    && direction == Direction::Positive
    && !axis.positiveJogPermitted()) {
    return CommandRejected::PositiveLimit;
}

if (command.isJog()
    && direction == Direction::Negative
    && !axis.negativeJogPermitted()) {
    return CommandRejected::NegativeLimit;
}
```

PLC仍是最终运动保护方，上位机检查用于提前反馈和减少无效通信命令。

### 7.4 删除旧枚举判断

禁止继续使用：

```cpp
if (alarmCode == 3) {
    // 推测软限位
}
```

原因：新的诊断字段是位集合，数值 3 可能表示两个位同时置位，不是互斥枚举。上位机应直接读取 `MotionConstraintBits`。

### 7.5 UI 展示

UI按类别显示：

- 运动限制：黄色状态提示，显示“仅允许反方向点动撤离，位置移动已禁止”；
- Warning：黄色消息，可确认，不锁住运动界面；
- AxisFault：红色故障，显示复位按钮和原始错误码；
- SystemFault：深红色故障，隐藏普通复位，提示联系管理员；
- LastCommandResult：短时提示或操作记录，不改变轴状态灯。

## 8. 协议兼容与迁移

### 8.1 推荐双轨过渡

在一个过渡版本中：

1. 保留现有 `告警码` 地址，只用于兼容旧上位机。
2. 新增 `MotionConstraintBits`、`WarningBits`、`AxisFaultBits`、`SystemFaultBits`。
3. PLC内部逻辑只使用新字段进行控制。
4. 旧 `告警码` 由新字段映射生成，禁止反向参与控制。
5. servoV6切换到新协议后，再停止维护旧字段。

兼容字段示例：

```st
旧告警码[轴号] := 0;
旧告警码[轴号].0 := 急停有效;
旧告警码[轴号].4 := 轴故障位[轴号].3;
旧告警码[轴号].5 := (轴故障位[轴号] <> 0);
旧告警码[轴号].6 := 警告提示位[轴号].0;
```

旧字段仅用于显示，不能作为新逻辑的运动许可条件。

### 8.2 协议版本

建议新增 `ProtocolVersion`：

- 旧版本：单一 `告警码`；
- 新版本：分类诊断和方向许可；
- servoV6启动时读取版本，不支持的版本禁止自动运行并给出明确提示。

## 9. 分阶段实施步骤

### 阶段0：冻结定义与安全评审

- 确认每个物理限位是工作限位还是安全极限限位。
- 确认各轴正负方向定义。
- 确认联动超差后的恢复方式。
- 确认哪些系统故障允许远程复位。
- 审计新增 Modbus 地址，避免与现有变量重叠。

交付物：评审通过的位定义、地址表和安全动作表。

### 阶段1：实现限位后的点动撤离规则

- 新增正负点动方向许可变量。
- 任意限位有效时拒绝全部绝对定位和相对定位。
- 运行中触发任意限位时终止全部位置移动。
- 点动只允许与当前限位相反的安全方向。
- 限位退出后自动清除状态。

该阶段不依赖完整告警拆分，应优先完成。

### 阶段2：拆分 PLC 诊断变量

- 新增四类状态字和详细错误码。
- 将原 bit1～bit3迁移为命令结果。
- 将 bit4迁移为联动超差轴故障。
- 将 bit5拆成驱动、轴、FB等故障。
- 将 bit6迁移为 Warning。
- 替换直接清零逻辑。

### 阶段3：改造 servoV6 协议与领域模型

- 更新寄存器映射。
- 增加 `AxisDiagnostics`。
- 状态推导只使用故障字段。
- 删除 `alarmCode != 0` 和 `alarmCode == 3` 逻辑。
- 修改定位、点动和联动策略。

### 阶段4：改造 UI 与复位流程

- 按类别显示诊断。
- 限位提示显示允许退出方向。
- 分开警告确认、轴复位和管理员故障。
- 显示轴、伺服和功能块原始错误码。

### 阶段5：联调、灰度和清理

- PLC模拟器完成全部测试矩阵。
- 单轴低速空载验证。
- 联动轴低速验证。
- 现场受控验证。
- 稳定运行一个发布周期后移除旧告警兼容逻辑。

## 11. 验收标准

满足以下全部条件才可认为改造完成：

1. 任意限位有效时，只允许安全方向点动撤离，所有绝对和相对定位均被禁止。
2. 只有限位输入释放并满足软件限位回差后，位置移动许可才自动恢复。
3. 软件限位退出后无需人工清除。
4. 点动心跳超时不会阻止后续定位。
5. 命令拒绝不会把轴状态设置为 Error。
6. 伺服、轴和功能块错误可分别识别并显示原始错误码。
7. `NOT 轴Status` 不再直接产生轴故障。
8. 活动故障不能被简单写零隐藏。
9. servoV6不存在 `alarmCode != 0` 和 `alarmCode == 3` 式的旧推导。
10. PLC与上位机协议版本不匹配时能明确拒绝运行。
11. 测试矩阵全部通过并保存测试记录。

## 12. 风险与回滚

### 12.1 主要风险

- 正负方向定义错误可能放开危险方向；
- 绝对轴和旋转轴的方向/周期处理可能不同；
- 硬限位可能实际属于安全极限，不能直接允许自动退出；
- PLC和servoV6不同步发布会造成状态解释错误；
- 地址重叠会污染其他控制变量。

### 12.2 风险控制

- 首次验证采用低速、低加速度、空载和人工急停监护；
- 为每轴分别验证方向，不只验证轴0；
- 使用协议版本阻止新旧程序错误组合；
- 过渡期保留旧字段只读映射；
- 发布前备份PLC工程和上位机可执行版本。

### 12.3 回滚条件

出现以下任一情况立即回滚：

- 限位方向判断与机械方向不一致；
- 限位有效时危险方向仍可运动；
- 故障位存在时仍能启动普通定位；
- 通信协议错位或寄存器值异常；
- 联动轴停止范围不符合安全要求。

## 13. 推荐实施优先级

最高优先级：

1. 修复定位限位的方向性判断。
2. 将点动心跳超时从阻断故障中移除。
3. servoV6取消“任意告警非零即Error”。

第二优先级：

1. 拆分 bit5。
2. 分离命令结果和轴故障。
3. 分离确认、复位和历史清除。

第三优先级：

1. 增加协议版本。
2. 增加事件序号和历史记录。
3. 完善管理员级系统故障流程。

---

本设计的最终判断原则是：

> 限位决定“只能向哪个方向点动撤离，并禁止全部位置移动”，轴故障决定“当前是否允许正常运动”，系统故障决定“是否需要维护人员介入”，操作提示只说明“上一条命令为什么没有执行”。
