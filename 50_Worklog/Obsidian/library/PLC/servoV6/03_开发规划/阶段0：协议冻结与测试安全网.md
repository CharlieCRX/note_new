阶段0的核心目标只有一个：把 PLC 通讯协议“钉死”，并建立测试安全网。此阶段不要重构 Domain、UI，也不要切换正式通讯路径。

对应规划见：[[02_PLC16槽位动态轴整体重构实施规划#6. 阶段0：协议冻结与测试安全网]]]。

## 一、PLC 协议确认清单

### 1. 槽位映射

- 确认槽位0–9固定对应 L0–L9。
- 确认槽位10–12固定对应 C0–C2。
- 确认槽位13–15固定对应 SYN0–SYN2。
- 确认槽位映射运行期间不会改变。
- 确认联动成员当前只允许 L0–L9。
- 确认 SYN0–SYN2分别对应 `联动轴信息[0..2]`。
- 确认上位机不需要维护 EtherCAT 实际电机编号。

### 2. 为每个 PLC 变量填写协议属性

每个变量都需要确认以下字段：

```
变量名
寄存器区：D / M
起始地址
数组长度
单项类型
单项占用字数
读写权限
默认值
单位
执行语义
由谁复位
是否有反馈
```

需要覆盖：

- 手动速度。
- 定位速度。
- 使能轴控。
- 相对原点清除。
- 绝对位置清零。
- 绝对定位触发。
- 相对定位触发。
- 点动正转。
- 点动反转。
- 报警解除触发。
- 使能电机。
- 相对定位终止触发。
- 绝对定位终止触发。
- 相对原点设置。
- 点动心跳。
- 告警码置零。
- 相对原点记录。
- 绝对定位距离。
- 相对定位距离。
- 软件负限位。
- 软件正限位。
- 超差阈值。
- 软限位控制。
- 职责。
- 绝对位置。
- 相对位置。
- 运动状态。
- 限位状态。
- 告警码。
- 联动成员信息。

- 设备急停。
- 设备急停解除。

## 二、数据类型与字节序清单

这是阶段0最容易遗漏、后期代价最高的部分。

### 1. Float32

- 确认手动速度为 IEEE 754 Float32。
- 确认定位速度为 Float32。
- 确认绝对/相对位置为 Float32。
- 确认定位目标、相对原点和软限位为 Float32。
- 确认每项 Float32占两个连续 D 字。
- 确认两个 D 字的高低字顺序。
- 确认每个 D 字内部的高低字节顺序。
- 确认负数的读取结果。
- 确认小数精度和有效范围。

建议在 PLC 中分别写入以下值，并记录原始两个 D 字：

- `0.0`
- `1.0`
- `-1.0`
- `20.0`
- `123.456`
- `-1000.0`

最终形成类似记录：

|浮点值|第一个D字|第二个D字|上位机读取结果|
|---|---|---|---|
|1.0|待记录|待记录|1.0|
|-1.0|待记录|待记录|-1.0|
|123.456|待记录|待记录|123.456|

### 2. UInt16和位域

- 确认职责为 UInt16，而不是 DINT/UInt32。
- 确认运动状态为 UInt16。
- 确认限位状态为 UInt16。
- 确认告警码为 UInt16位域。
- 确认软限位控制为 UInt16位域。
- 确认上位机不得按有符号 INT16解释职责有效位。

## 三、状态编码确认清单

### 1. 运动状态

逐项在真实 PLC 中验证：

- `0`：使能轴控关闭。
- `1`：空闲。
- `2`：正向点动。
- `3`：反向点动。
- `4`：绝对定位中。
- `5`：相对定位中。
- 告警发生时运动状态如何显示。
- 电机未使能但轴控使能时状态值是什么。
- 定位完成后是否稳定回到1。
- 停止触发后经过什么状态变化。

### 2. 限位状态

- `0`：无限位。
- `1`：软件正限位。
- `2`：软件负限位。
- `3`：硬件正限位。
- `4`：硬件负限位。
- 同时出现软限位和硬限位时的优先级。
- 限位解除后何时恢复0。
- 限位期间反方向点动是否允许。
- 限位期间定位是否全部禁止。

### 3. 告警位

请与 PLC 开发人员逐位确认，形成正式表格：

|位|当前理解|已确认|
|---|---|---|
|0|设备急停|[ ]|
|1|联动成员冲突|[ ]|
|2|加入联动时超差|[ ]|
|3|联动成员配置错误|[ ]|
|4|运行中联动超差|[ ]|
|5|运动功能块/伺服错误|[ ]|
|6|点动心跳超时|[ ]|
|7–15|保留|[ ]|

还要确认：

- 多个告警能否同时置位。
- 告警位是否锁存。
- `告警码置零`清除哪些告警位。
- 告警原因仍存在时，清零后是否立即重新置位。
- `报警解除触发`负责伺服Reset，不等于告警码置零。
- 报警解除PLC逻辑未加入前，上位机应返回“不支持”。

## 四、命令执行语义清单

将每个 M 变量归类为电平、PLC自复位触发或周期心跳。

### 1. 电平量

- `使能轴控`：ON/OFF持续有效。
- `使能电机`：ON/OFF持续有效。
- `点动正转`：按下ON、松开OFF。
- `点动反转`：按下ON、松开OFF。
- `设备急停`：写ON后持续保持还是 PLC 自行处理。

### 2. PLC 自复位触发

逐项确认 PLC 是否检测上升沿，并由 PLC 清回 OFF：

- 相对原点清除。
- 绝对位置清零。
- 绝对定位触发。
- 相对定位触发。
- 报警解除触发。
- 相对定位终止触发。
- 绝对定位终止触发。
- 相对原点设置。
- 告警码置零。
- 设备急停解除。

对每个触发还要确认：

- PLC 是上升沿触发还是 ON 电平触发。
- PLC 在哪个扫描周期清回 OFF。
- 上位机只写一次 ON 是否足够。
- 连续重复写 ON 是否会重复执行。
- 执行条件不满足时，PLC 会清除还是保留。
- 是否存在完成反馈。
- 触发失败如何反馈。

### 3. 点动心跳

- 心跳超时固定为3000ms。
- 点动期间上位机应多久发送一次。
- 建议发送周期500–1000ms是否可接受。
- 心跳是写 ON，随后由 PLC 清回 OFF。
- 未点动时是否需要心跳。
- 正反点动共用同一个心跳。
- 心跳超时后 PLC 会清除正反点动命令。
- 心跳超时后告警 bit6是否锁存。
- 告警清除后是否允许重新点动。

## 五、定位协议确认清单

### 1. 绝对定位

- 先写 `绝对定位距离[slot]`。
- 再写 `绝对定位触发[slot]=ON`。
- 设置目标本身不启动运动。
- 触发不会隐式修改目标。
- 目标等于当前位置时 PLC 如何处理。
- 正在运动时重新写目标是否允许。
- 正在运动时再次触发如何处理。
- 绝对定位终止触发的执行条件。
- 终止后绝对定位触发是否自动清除。

### 2. 相对定位

- 先写 `相对定位距离[slot]`。
- 再写 `相对定位触发[slot]=ON`。
- 设置距离本身不启动运动。
- 距离为0时 PLC 如何处理。
- 正在运动时重新写距离是否允许。
- 正在运动时再次触发如何处理。
- 相对定位终止触发的执行条件。
- 终止后相对定位触发是否自动清除。

### 3. 上位机接口结论

- 确认保留 `setAbsTarget()`。
- 确认保留 `triggerAbsMove()`。
- 确认保留 `setRelTarget()`。
- 确认保留 `triggerRelMove()`。
- 确认不增加合并定位接口。

## 六、职责协议清单

### 1. 位定义

- bit0：A/B分组。
- bit1–3：功能轴。
- bit4：UI展示。
- bit5–8：主轴槽位。
- bit9–12：从轴槽位。
- bit13：联动配置。
- bit14：保留且必须为0。
- bit15：职责有效位。
- 确认功能码0–5分别对应 X/X1/X2/Y/Z/R。
- 确认功能码6、7非法。
- 确认职责只用于启动配置。

### 2. 建议测试向量

请在 PLC 和上位机分别解码以下值：

|原始值|预期|
|---|---|
|`0x0000`|未配置|
|`0x8012`|A组、X1、UI展示、有效|
|`0x8016`|A组、Y、UI展示、有效|
|`0x801B`|B组、R、UI展示、有效|
|`0xA210`|A组、X、UI展示、主轴0、从轴1、配置联动、有效|

- PLC侧计算结果与预期一致。
- C++侧计算结果与预期一致。
- bit15不会因有符号类型产生错误。
- 非X轴的主从字段配置端统一写0。
- 未配置职责统一写0。

### 3. CRC阶段结论

- 阶段0确认 CRC32方案，但不要求立即实现。
- 不在单个职责字中放CRC。
- 第一阶段至少采用有效位和语义校验。
- 预留 Magic、SchemaVersion、Generation、CRC32配置头方案。
- 确认配置头未来由 PLC 还是配置工具维护。

## 七、急停语义清单

按照当前已确认方案：

- M224写 ON 成功后，上位机立即认为已经急停。
- 急停后禁止全部普通轴控制。
- 急停期间仍允许读取位置、状态和告警。
- 急停期间仍允许执行急停解除。
- 急停解除通过 M225触发。
- M225写入成功后，上位机解除本地急停状态。
- 明确记录“当前没有独立急停反馈”的限制。
- 明确 Modbus写成功不等于机械系统已经物理停稳。

## 八、上位机测试安全网清单

### 1. 协议层测试

- Float32编解码测试。
- UInt16编解码测试。
- Bool读写测试。
- 槽位0和15边界测试。
- 槽位16拒绝测试。
- 16槽位所有地址公式测试。
- 职责位掩码测试。
- 职责非法功能码测试。
- 职责保留位测试。
- 职责有效位测试。

### 2. Modbus快照测试

- 完整响应生成可信快照。
- 任意读取失败生成不可信快照。
- 失败时不使用全零伪装正常状态。
- 快照带时间戳。
- 断线后停止有效反馈更新。
- 重连后可以重新建立可信快照。

### 3. 命令测试

- 设置绝对目标只写目标寄存器。
- 绝对触发只写触发寄存器。
- 设置相对距离只写距离寄存器。
- 相对触发只写触发寄存器。
- 目标写失败不会继续触发。
- 触发命令不会在重连后自动重放。
- 点动停止优先于普通参数写入。
- 急停优先于所有普通轴命令。

### 4. 现有行为特征测试

在重构前记录现有系统：

- 启动连接流程。
- 正向点动。
- 反向点动。
- 点动停止。
- 绝对目标设置。
- 绝对定位触发。
- 相对距离设置。
- 相对定位触发。
- 定位终止。
- 相对零点设置/清除。
- 绝对位置清零。
- 速度设置。
- 急停与解除。
- 网络断开与重连。

每项至少保存：

```
前置状态
用户操作
调用链
PLC写入地址和值
PLC反馈变化
上位机最终状态
异常行为或已知缺陷
```

这里的目标是记录现状，不是要求保留已经确认的旧缺陷。

## 十、阶段0明确不要做的事情

- 不修改 `Axis`继承结构。
- 不创建 `SingleAxis/CoupledAxis`。
- 不修改 UI功能轴映射。
- 不删除旧 `AxisId`。
- 不删除旧寄存器表。
- 不切换正式轮询路径。
- 不让新代码真实控制生产设备。
- 不同时修改 PLC协议和上位机架构。
- 不因为 CRC 尚未实现而阻塞其他协议确认。
- 不用“应该是”代替真实 PLC 测试。
