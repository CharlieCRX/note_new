> 未来一年，我能不能发现100个真实问题？

## 《工程师痛点库》

每次遇到一个问题，只写六项。

例如昨天：

|字段|内容|
|---|---|
|场景|新板卡接 HCM360B|
|目标|RS485 读取姿态数据|
|痛点|串口正常，但设备不响应|
|排查耗时|假设 3h|
|最终原因|A/B 接线不稳定|
|如果有工具|自动判断链路/电气/协议问题|

然后增加最重要的一栏：

> **这个问题是不是别人也会遇到？**

评分：

```
频率        ★★★★☆
痛苦程度    ★★★★☆
愿意付费    ★★★☆☆
现有方案差  ★★★★☆
我能不能做  ★★★★★
```

例如你现在的工作环境里，我已经能看到一堆：

```
01 新板 UART 验证很麻烦

02 RS485 出问题不知道是软件还是硬件

03 新芯片上电以后不知道是否正常

04 datasheet 很长，初始化流程容易遗漏

05 手工构造十六进制协议容易出错

06 CRC/Checksum 经常算错

07 串口助手无法很好复现嵌入式现场

08 驱动开发之前缺少标准验证流程

09 GPIO/I2C/SPI/UART bring-up 重复劳动

10 硬件工程师和软件工程师之间信息断层

11 板卡没有标准自检机制

12 现场 bug 很难复现

13 示波器/逻辑分析仪门槛高

14 Linux设备节点和硬件接口映射难查

15 硬件电路出了问题软件工程师很难判断
```

注意：

这里已经不是一个产品。

而是：一个“问题空间”。

每天观察：

```
客户为什么抱怨？

硬件工程师为什么痛苦？

软件工程师为什么痛苦？

测试人员为什么痛苦？

哪些事情一直重复？

哪些设备特别贵？

哪些软件特别难用？

哪些步骤只能靠老师傅？

哪些东西一坏大家就抓瞎？
```

## 赚到陌生人的第一块钱

不是10万。

不是100万。

就是：

> **￥1。**

因为你现在最缺的不是钱。

你缺少的是这条完整反馈：

```
我发现问题

↓

我做解决方案

↓
```
