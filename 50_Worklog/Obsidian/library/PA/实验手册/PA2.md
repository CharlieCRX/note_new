# 理解YEMU如何执行程序

## 加法程序的状态机

状态机只是为了展示核心状态信息的变化。

```C
#define NREG 4
#define NMEM 16

uint8_t pc = 0;       // PC, C语言中没有4位的数据类型, 我们采用8位类型来表示
uint8_t R[NREG] = {}; // 寄存器
uint8_t M[NMEM] = {   // 内存, 其中包含一个计算z = x + y的程序
  0b11100110,  // load  6#     | R[0] <- M[y]
  0b00000100,  // mov   r1, r0 | R[1] <- R[0]
  0b11100101,  // load  5#     | R[0] <- M[x]
  0b00010001,  // add   r0, r1 | R[0] <- R[0] + R[1]
  0b11110111,  // store 7#     | M[z] <- R[0]
  0b00010000,  // x = 16
  0b00100001,  // y = 33
  0b00000000,  // z = 0
};
```

在这个加法程序中，哪些寄存器和内存涉及到了信息的变化：

- `R[2]` 和 `R[3]` 根本没被用到（永远是 0）。
- `M[0]` 到 `M[4]` 是指令，`M[5]` (x) 和 `M[6]` (y) 是只读数据，它们在运行中**绝对不会改变**。
- 真正在变化的关键部件只有：**`PC`、`R[0]`、`R[1]`、`M[7]` (z)**。

因此，我们可以把这个巨大系统的状态，简化为一个四元组：`<PC, M[7] R[0], R[1],>`。

定义好四元组的状态机后，画出在YEMU上执行的加法程序的状态机：

|  PC  | M[7] | R[0] | R[1] |
| :--: | :--: | :--: | :--: |
|  0   |  x   |  x   |  x   |
|  1   |  x   |  33  |  x   |
|  2   |  x   |  33  |  33  |
|  3   |  x   |  16  |  33  |
|  4   |  49  |  16  |  33  |

## YEMU如何执行一条指令

我们就以`pc = 0`的时候，看下YEMU 代码如何执行第一条指令：`0b11100110`。

- ` exec_once()`：
  - `this.inst = M[0] =  0b11100110`
  - `uint8_t addr = (inst).mtype.addr = 0b0110 = 6;`
  - ` R[0]    = M[6] = 33(y);`
- `pc = 0 + 1 = 1`

# 了解指令确切的行为

指导提到：

> 无论你选择何种ISA, 相应手册中一般都会有以下内容, 尝试RTFM并寻找这些内容的位置:
>
> - 每一条指令具体行为的描述
> - 指令opcode的编码表格

这里举例`ADD`指令为例的阅读导览：

以 `ADD` 这一最基础的整数加法指令为例，在手册中高效查找和理解它的全貌，建议遵循“**语义定义 -> 格式结构 -> 机器码编码**”的逻辑顺序进行阅读：

## 1. 查询指令语义与行为 (Section 2.4.2)

首先需要明确指令的具体计算行为以及它如何操作寄存器。前往 **第2.4.2节 (Integer Register-Register Instructions)**。  

- **行为描述**：手册在此处指出，`ADD` 执行 `rs1` 和 `rs2` 的加法，溢出（Overflows）会被直接忽略，并将结果的低 XLEN 位写入目标寄存器 `rd`。  
- **架构设计体现**：在这里可以清晰地看到它采用了标准的 3 地址格式（两个源寄存器 `rs1/rs2`，一个目标寄存器 `rd`）。这种设计保留了源操作数不被破坏，在微架构实现中极大地方便了编译器进行高效的寄存器分配。

## 2. 解析指令格式 (Section 2.2 & 2.4.2)

明确了功能后，需要知道它在二进制层面是如何划分位段的。

- 在 2.4.2 节头部的图示中，标明了 `ADD` 等算术指令属于 **R-Type** 格式。  

- 结合 **第2.2节 (Base Instruction Formats)** 中关于 R-Type 的通用定义，你可以查到这条 32 位指令的严格对齐划分：

  ```text
  funct7 (7位) | rs2 (5位) | rs1 (5位) | funct3 (3位) | rd (5位) | opcode (7位)
  ```

## 3. 查阅具体机器码 (Chapter 36 & Section 2.4.2)

最后一步是获取这根指令的“身份证号”，即它独有的二进制特征码。

- 同样在 2.4.2 节的指令列表中，给出了 `ADD` 特有的微码标识：`funct7 = 0000000`，以及主操作码分类属于 `OP`。`funct3` 这一列只是用助记符（如 `ADD/SLT[U]`）对指令进行了分组，并没有直接标出 `000` 这个具体的二进制值。  
- 为了确认 `OP` 具体对应的 7 位二进制码（这在写解码器时非常关键），你需要翻到作为“字典”的 **第36章 (RV32/64G Instruction Set Listings)**。在这里的大表中可以查出 `OP` 对应的 opcode 编码是 `0110011`。
- 当你翻到那一章（**第36章 (RV32/64G Instruction Set Listings)**）的大表并找到 `ADD` 时，每一位都会被毫无歧义地列出：`funct7=0000000`、`funct3=000` 以及 `opcode=0110011`

通过这三步，一条 `ADD` 指令从算术语义，到 3 地址格式的寄存器索引，再到最终构成的 32 位机器码就彻底贯通了。
