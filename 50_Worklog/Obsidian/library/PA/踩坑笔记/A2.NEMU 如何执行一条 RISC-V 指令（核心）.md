# NEMU 如何执行一条 RISC-V 指令

## 核心问题

NEMU 如何从 `cpu.pc = 0x80000000`， 执行第一条： 

```C
auipc t0, 0 
```

并最终得到： 

```C
t0 = 0x80000000 pc = 0x80000004
```

## 一、单条指令执行链

```text
cpu->pc = 0x80000000
|
exec_once
|
s->pc = s->snpc = cpu.pc
|
isa_exec_once
|
inst_fetch(&s->snpc, 4)
|	|_ s->isa.inst = 0x297
|	|_ s->snpc = 0x80000004
|
decode_exec
|	|_ s->dnpc = s->snpc = 0x80000004
|	|_ 匹配 AUIPC
|	|_ decode_operand(TYPE_U)
|	|_ gpr[rd] = pc + imm
|	
cpu.pc = s->dnpc = 0x80000004
```

## 二、AUIPC 实例

指令：

```C
0x00000297,  // auipc t0,0
```

译码：

```text
opcode = 0010111 → AUIPC
```

```
rd = 5(t0)
imm = 0
```

执行:

```
gpr[5] = 0x80000000 + 0
       = 0x80000000
```

执行结束：

```
cpu.pc = 0x80000004
```

## 三、decode_exec 的本质

decode_exec 解决了三个问题：

1. 这是什么指令？

   `pattern_decode()`

   - pattern 转成 key/mask/shift
   - 与`s->isa.inst`比较

2. 这条指令的操作数是什么？

   `decode_operand()`

   - 根据 TYPE 类型
   - 提取 imm / rd / rs1 /rs2 

3. 这条指令要做什么？

   执行 `INSTPAT` 的 body

最后：
`dnpc` 决定下一条指令地址。

## 四、易错点

1. `inst_fetch` 会推进 `snpc`；
2. `decode_exec`不直接修改 `cpu.pc`，只决定`dnpc`；
3. `cpu.pc`更新发生在执行`isa_exec_once()`结束后；
4. 匹配成功后 `goto INSTPAT_END`，不再继续匹配后面的指令。
5. 最后 R(0)=0 保证 RISC-V x0 恒为 0。

## 五、验证手段

宏过于复杂时：

```
make -nB
→ 获取真实 gcc 参数（把这条 gcc 需要的 -I（头文件在哪）和 -D（宏定义）原样给它）
→ -c 改为 -E
→ 查看预处理后的 decode_exec
```

原则：
不要猜宏展开结果，让编译器告诉我。
